# 文字菜单管理 · Copy Bar

一个用于整理 Android 长按文字菜单中**文字处理扩展**的 LSPosed 模块。只需勾选「系统框架」，在系统返回标准扩展列表时按规则过滤。

当前版本：**0.4-clarity**。项目仍在早期开发阶段，厂商兼容性有限。

## 已实现

- 按扩展组件单独屏蔽、按所属应用包名屏蔽，或隐藏全部标准扩展。
- 系统应用与第三方应用分组展示，显示名称、所属应用和组件标识。
- 开关开启表示屏蔽，旁边显示「已屏蔽／未屏蔽」。全局隐藏和包名规则优先于单项选择。
- 显示系统框架连接及共享配置读取状态。
- 中文、英文、中英混合、网址、数字、自定义六种真实菜单预览；支持编辑、粘贴、选择全部和重建预览。
- 卡片布局、浅色与深色主题。

## 支持范围

| 内容 | 当前状态 |
| --- | --- |
| 应用通过 ACTION_PROCESS_TEXT 注册的标准文字处理扩展 | 已实现过滤 |
| 系统应用注册的标准文字处理扩展 | 与第三方扩展同样处理，受当前用户与查询可见性限制 |
| 系统复制、剪切、粘贴、全选 | 当前版本不控制 |
| 小米「问小爱、AI 写作、小爱翻译」等专用菜单 | 已定位实现线索，**尚未适配** |
| 应用自绘菜单、非标准查询流程 | 不保证覆盖 |
| 自动发现并控制小米动态菜单 | 已讨论方案，**尚未实现** |

这里的「按包名屏蔽」仅作用于标准文字扩展查询结果，不会冻结应用，也不会屏蔽该应用提供的所有菜单功能。

## 安装使用

前提：Android 12 或以上，以及支持传统 Xposed API 和共享偏好设置的 LSPosed 环境。最低 API 为 31，不能据此推断所有 Android 12–16 系统都已通过兼容验证。

1. 安装自行构建并签名的 APK。
2. 在 LSPosed 中启用「文字菜单管理」，作用域勾选 **系统框架（android）**。当前标准扩展过滤不需要逐个勾选目标应用。
3. 首次启用或更新模块后重启手机，打开应用检查框架状态。
4. 开启需要屏蔽的项目；配置通常在约一秒后重新读取。
5. 关闭旧菜单、重建预览，再长按文字检查。若目标应用缓存了扩展列表，需重新启动该应用。

「未屏蔽」只表示该组件没有单独设置屏蔽；若启用隐藏全部或所属包名规则，仍会被过滤。关闭总开关则停止实际过滤。

## 已知限制与验证

- 用户反馈标准扩展过滤基本可用。只读诊断环境为 Android 16 / HyperOS OS3.0.7.0.WOBCNXM；这不代表所有功能或设备已验证。
- 小米专用入口由 MiuixEditor 直接生成，不走标准 PROCESS_TEXT 查询；添加超级小爱包名不能屏蔽这些入口。
- 预览展示本应用的真实菜单，不模拟其他应用的自定义菜单。
- 新版代码通过构建、单元测试与 lint 检查；lint 仍有警告。早期 Android 13 菜单函数测试不等于当前系统层 Hook 的端到端覆盖。
- 不跨用户或工作资料扫描，不主动绕过系统包可见性。
- 管理查询使用专用标记绕过过滤，以便恢复被隐藏项目；它不是安全边界，本模块不能用作访问控制。

更多实现、故障定位、验证边界和未完成事项见 [详细开发文档](docs/DEVELOPMENT.md)。

## 构建

环境：JDK 21、Android SDK 36.1、Gradle Wrapper 9.4.1、AGP 9.2.1。配置本地 SDK 路径后运行：

```powershell
./gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
./gradlew.bat :app:assembleRelease
```

Debug 输出位于 app/build/outputs/apk/debug/。项目未内置 Release 签名配置，Release 默认输出未签名包，需要使用自己的密钥签名。此前个人测试包使用本机 Debug 密钥签署；密钥不包含在仓库中。

## 数据与隐私

模块代码不主动收集、记录或上传所选文字和剪贴板内容。共享规则包含屏蔽包名与组件，可被相关进程读取，不能当作私密存储。预览使用系统文本控件，系统及用户启用的扩展如何处理文字由其各自决定。仓库不包含从设备导出的系统 APK、反编译源码、设备日志或签名密钥。
